- Hashing and saving (found in the bug hunt): `Sim::stateHash` does not cover every system's own state (social, mental breaks, prisoners, fighters, combat, melee, defense and explosives keep state the hash skips; only their per-thing parts are in it), so the replay compare in CI cannot see a difference there until it reaches a hashed thing. `SaveSoakTests` compares the loaded game with the one that kept running step by step and would catch more if the hash grew. Also: saves list things in registry order, which a load changes, so two saves of the same game can differ in bytes; a canonical (id) order would let tests compare bytes. Never keep a component reference across `Things::destroy` (it moves the last component into the freed slot): destroy last.
